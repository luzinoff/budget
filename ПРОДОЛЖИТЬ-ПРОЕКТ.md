# Приложение учёта бюджета — передача проекта

Это описание текущего состояния проекта: что уже сделано, как устроено, как развернуть с нуля и что нельзя ломать при доработке.

Чтобы продолжить работу с Клодом на другом компьютере, откройте разговор со словами «продолжаем проект учёта бюджета» и дайте доступ к папке с этими файлами. Всё нужное изложено ниже.

## Состав папки

| Файл | Назначение |
|---|---|
| `index.html` | Всё приложение целиком: разметка, стили, логика. Единственный файл, который правится. |
| `sw.js` | Service worker — офлайн-режим и кэш |
| `manifest.webmanifest` | Манифест PWA: имя, иконки, цвета, запуск в отдельном окне |
| `icon.svg`, `icon-maskable.svg` | Иконки приложения |
| `Бюджет-копия-ГГГГ-ММ-ДД.json` | Резервная копия данных, выгруженная из приложения |
| `ПРОДОЛЖИТЬ-ПРОЕКТ.md` | Этот файл |

---

## Что это

Личный учёт доходов и расходов для человека, живущего во Вьетнаме: часть денег в рублях, часть во вьетнамских донгах. Начиналось как таблица в Excel, затем стало одностраничным приложением, а сейчас — PWA, размещённая на GitHub Pages и синхронизируемая через Google Диск.

Чистый JavaScript, без фреймворков, без сборки, без пакетов. Правится текстовым редактором, выкладывается копированием файлов. Единственная внешняя зависимость — скрипт входа Google, и тот подгружается только когда пользователь сам нажал синхронизацию.

Данные хранятся в `localStorage` браузера под ключом `budget.v1`, а их копия — в скрытой служебной папке Google Диска.

## Требования пользователя — их нельзя нарушать при доработке

Донги **не пересчитываются** в рубли. Это принципиально: две валюты живут раздельно, курс не нужен.

Комментарий и способ оплаты относятся **к каждой отдельной записи**, а не к категории. Поэтому данные хранятся журналом транзакций, а не таблицей «день × категория» — в ячейку таблицы это не помещается.

Ввод даты, категории и способа оплаты — **только выбором**, кнопками-чипами. Руками вводятся лишь сумма и комментарий; ещё есть диктовка голосом.

## Что умеет

Пять вкладок в порядке слева направо: Расходы ₫, Наличные ₫, Доходы ₽, Расходы ₽, Итоги. Открывается приложение на «Расходы ₫» — это самая частая операция. Сверху переключатель месяца и года; если выбранный год выходит за диапазон списка, недостающий год подставляется сам.

Донговые расходы группируются по дням с подытогом на каждый день. Есть итог месяца, разбивка по категориям и по способам оплаты с процентами, и среднее по дням, в которые были траты.

Наличные: вводится остаток на начало месяца, отмечаются пополнения, и на каждый день считается остаток с учётом трат наличными за этот день. Дни без движения не показываются.

Диктовка: кнопка микрофона в каждой форме использует Web Speech API. Разбирает суммы цифрами и словами, множители «тыщ», «лям», «млн», категории и способы оплаты по ключевым словам, а текст в кавычках кладёт в комментарий. Дату понимает как «сегодня», «вчера», «позавчера» или цифрой — «15 числа», «15го»; словесные порядковые вроде «пятнадцатого» не распознаются. Если названная дата попадает в другой месяц, приложение переключит месяц целиком. Работает в Chrome; в браузерах без поддержки кнопка просто отключена.

Синхронизация с Google Диском работает сама: после первого входа приложение обменивается данными при запуске, после каждой правки, при возврате к вкладке и при закрытии — без единого нажатия. Точка в шапке показывает состояние, и в неё же выносится просьба войти заново, если разрешение протухло.

На вкладке «Итоги» — настройки синхронизации и работа с файлами: выгрузка копии в JSON, загрузка обратно в двух режимах (объединить или заменить) и выгрузка в CSV для Excel с BOM, разделителем `;` и запятой в дробной части, чтобы русский Excel открыл корректно.

Этого нет ни в одном файле папки, и восстановить по коду невозможно. Впишите сюда прямо сейчас, иначе на новом компьютере придётся вспоминать.

- Репозиторий: `https://github.com/______/______`
- Адрес сайта: `https://______.github.io/______/`
- Проект в Google Cloud Console: `______`

Client ID не секрет — он по замыслу виден в браузере любому, кто откроет сайт, а доступ ограничен списком разрешённых origin в консоли Google. Записывать его сюда безопасно, и это избавит от похода в консоль при настройке нового устройства.

## Развёртывание

### 1. GitHub Pages

Все файлы кладутся в корень репозитория. В настройках репозитория раздел Pages, источник — ветка `main`, папка `/ (root)`. Через минуту сайт доступен по адресу `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/`.

Репозиторий может быть публичным — в коде нет секретов. Client ID секретом не является, он по замыслу виден в браузере; доступ ограничивается списком разрешённых адресов в консоли Google, а не скрытностью идентификатора.

HTTPS обязателен. Проверка одна на всё — `const httpsOk = location.protocol === "https:"`, и ею закрыты и вход в Google, и регистрация service worker. Практическое следствие: при открытии файла двойным кликом синхронизации и офлайна не будет, о чём приложение честно пишет в интерфейсе. Но и на `http://localhost` тоже — хотя браузер там service worker разрешает, этот код его не включит. Значит офлайн-режим проверяется только на выложенном сайте; для локальной разработки это нормально, вёрстка и вся логика ввода работают и с файла.

### 2. Client ID для Google Диска

В [Google Cloud Console](https://console.cloud.google.com/) создайте проект. Включите **Google Drive API**. В разделе OAuth consent screen выберите тип External, заполните название и почту, а в списке тестовых пользователей добавьте свой гугл-аккаунт. Приложение можно навсегда оставить в статусе тестового — проверка Google для личного использования не нужна, надо лишь раз в полгода подтверждать доступ заново.

Область доступа — только `drive.appdata`. Это самый узкий скоуп из существующих: приложение видит исключительно свой файл в скрытой папке и не имеет доступа к остальному Диску. Обычно он не требует верификации.

Затем Credentials → Create credentials → OAuth client ID → тип **Web application**. В поле **Authorized JavaScript origins** впишите адрес без пути и без слэша на конце:

```
https://ИМЯ.github.io
```

Именно origin, а не полный адрес страницы. Это самое частое место ошибки: при несовпадении вход падает с невнятным сообщением. Поле Authorized redirect URIs заполнять не нужно — используется токен-клиент, а не редирект.

Полученный Client ID вставьте в приложении на вкладке «Итоги» в поле Client ID и нажмите «Сохранить». Он останется в этом браузере; на втором устройстве вводится тот же самый.

### 3. Установка на телефон

Откройте адрес в Chrome, меню → «Установить приложение». Появится иконка на рабочем столе, запуск в отдельном окне без адресной строки, работа офлайн.

### 4. Выкладка обновлений

**При каждом изменении файлов поднимайте номер в `sw.js`:** `const CACHE = "budget-v3"` → `budget-v4`. Иначе часть устройств останется на старой версии из кэша. Сама страница берётся из сети с откатом на кэш, так что обновления доезжают быстро, но остальные файлы кэшируются жёстко.

## Модель данных

```js
DB["ГГГГ-ММ"] = {
  inc:   [],   // доходы, ₽
  rub:   [],   // расходы, ₽
  vnd:   [],   // расходы, ₫
  topup: [],   // пополнения налички, ₫
  cashStart: 0,      // остаток налички на начало месяца, ₫
  cashStartTs: 1     // когда остаток менялся — для слияния
}
```

Запись: `{ id, day, amount, note, cat, pay, ts, del }`.

`id` уникален и неизменен, `ts` — момент последней правки, `del` — момент удаления (0 у живой записи). Поле `pay` заполняется только у донговых расходов.

**Удаление не стирает запись, а помечает её.** Иначе стёртое на одном устройстве воскресало бы с Диска на другом. Такие «надгробия» живут 90 дней (`TOMB_TTL`), после чего вычищаются в `prune()`. Наружу, в интерфейс, отдаются только живые записи — за это отвечает `mon()`, тогда как `monW()` даёт полный доступ для записи.

## Синхронизация

Вход через Google Identity Services, обращения к Drive API напрямую через `fetch`. Один файл `budget.v1.json` в папке `appDataFolder`.

Порядок работы `syncNow()`: получить токен, найти файл на Диске, скачать, слить с локальной базой, сохранить результат и локально, и на Диск.

`mergeDB()` объединяет две базы по `id` записи: побеждает бо́льший `ts`, а при равенстве — удаление. Остаток налички сливается отдельно по `cashStartTs`. Благодаря этому порядок работы устройств не имеет значения и офлайн безопасен.

Автосинхронизация запускается через 2 секунды после правки. Живого токена для этого не требуется: достаточно, чтобы вход когда-то был сделан — этот факт хранится в `localStorage["budget.auth"]` (в памяти — `SYNC.ever`), потому что сам токен живёт только в памяти вкладки и теряется при перезагрузке. Благодаря флагу приложение продлевает токен молча, с `prompt:"none"`, и обменивается данными само: при запуске, после каждой правки, при возврате к вкладке и при закрытии страницы. Флаг `SYNC.pending` следит, чтобы правка, сделанная во время выгрузки, не потерялась, а `flushSync()` дожимает отложенную правку на `pagehide`.

Тихое продление может не пройти — Google разлогинен, почищены куки, Safari или Firefox режут сторонние куки. Тогда взводится `SYNC.relogin`: автосинхронизация замолкает до нажатия кнопки, а на «Итогах» появляется просьба войти заново. **Окно входа Google в фоне не открывается никогда** — только по нажатию «Войти и синхронизировать». Это главное правило этого блока: всплывающее окно, выскочившее само по себе, пользователь воспринимает как поломку. За разделение отвечает закрытый список `AUTH_MSGS`; ошибки Диска и таймауты сети в него не входят, они лечатся повтором.

Сорванный обмен повторяется сам с нарастающей паузой (`SYNC.fails`, от 5 секунд до минуты, таймер `SYNC.retry`). Повтор намеренно держится отдельно от таймера автоотправки `SYNC.timer`: иначе `flushSync()` принял бы его за отложенную правку и обнулял выдержку на каждое сворачивание приложения.

Возврат к вкладке синхронизирует не чаще раза в 30 секунд — на телефоне переключение между приложениями иначе гоняло бы полный цикл записи на Диск.

Отключение синхронизации во время летящего запроса обработано через счётчик поколений `SYNC.gen`: `authOff()` увеличивает его, а начатый обмен сверяет своё поколение на каждом шаге и тихо сходит с дистанции. Без этого прилетевший позже ответ Google снова записал бы флаг входа, и отключение отменялось бы само собой. По той же причине `authOff()` гасит таймеры и снимает `SYNC.busy`, а событие `storage` разносит отключение по остальным открытым вкладкам.

Отдельно обработан редкий случай: если два устройства синхронизировались впервые одновременно, на Диске может появиться два файла. Тогда берётся старейший как основной, остальные сливаются в него и удаляются — но только после успешной записи.

Точка на вкладке «Итоги» показывает состояние: серая — выключено, зелёная — подключено, красная — ошибка. Фоновые сбои тоже красят её и пишут причину: молчать об этом нельзя, иначе пользователь решит, что данные в безопасности.

## Уже исправленные проблемы — не сломать повторно

Импорт JSON проверяет данные через `isObj()`. Поскольку `typeof null === "object"`, файл с `null` раньше затирал всю базу без возможности восстановления. Каждая запись при загрузке нормализуется в `fix()`, а ключи месяцев проверяются регулярным выражением.

Режим «Заменить из копии» не выбрасывает записи молча, а помечает удалёнными с текущей меткой времени. Иначе синхронизация вернула бы их с Диска и замена оказалась бы мнимой.

Поле остатка налички не перерисовывается, пока в нём стоит курсор, иначе ввод стирался на каждом нажатии. Сохранение отложено на 400 мс, потому что `save()` прогоняет `prune()` по всей базе. И `cashStartTs` не обновляется, если значение не изменилось: иначе простой заход в поле создал бы свежую метку с нулём и затёр остаток с другого устройства.

Суммы вводятся в поля `type="text" inputmode="decimal"` и разбираются функцией `parseAmt()`, которая понимает запятую, точку и пробелы-разделители тысяч. С `type="number"` браузер возвращал пустую строку на «1,5».

В CSV текст, начинающийся с `=`, `+`, `-`, `@`, экранируется апострофом — иначе Excel исполнит его как формулу.

Все данные пользователя выводятся через `textContent`, не через `innerHTML`.

`buildForm(key, scroll)` принимает второй аргумент, поэтому её нельзя передавать напрямую в `forEach` — индекс массива попадёт в `scroll` и страница будет прыгать.

`setTab()` вызывается после `render()`, иначе лента дней пересобирается и прокрутка сбрасывается.

Service worker не трогает запросы к чужим доменам: закэшированный ответ Google сломал бы вход.

## Ограничение окружения

На машине пользователя отключена аппаратная виртуализация, изолированная Linux-среда не запускается (`HYPERVISOR_VIRT_DISABLED`). Значит, у Клода нет bash, Python и node. Файлы правятся текстовыми инструментами, а код проверяется чтением и ревью, а не запуском. Проверять поведение нужно в браузере вручную.

## Возможные доработки

Иконки сейчас только в SVG. Chrome на Android их понимает, но некоторые лаунчеры и iOS — нет, поэтому PNG 192×192 и 512×512 не помешают.

Упаковка в настоящий APK через Capacitor, если PWA окажется недостаточно. Практической разницы почти нет: PWA уже даёт иконку, офлайн и полноэкранный запуск.

Диктовка опирается на Web Speech API, который в Chrome отправляет звук на серверы Google. Офлайн она не работает.

## Переезд на другой компьютер

Исходники самодостаточны: скопируйте папку целиком, и разработку можно продолжать. Ничего не собирается и не устанавливается.

Но три вещи живут вне папки и переносом файлов не подхватываются.

**Данные.** Они в `localStorage` браузера, а не в файлах. Перед переездом откройте «Итоги» → «Сохранить копию» и возьмите свежий JSON с собой; на новом месте — «Объединить с копией». Лежащая в папке копия датирована днём выгрузки и с тех пор устарела. Если синхронизация с Диском уже настроена, проще войти в неё на новом устройстве — данные приедут сами.

**Client ID.** Хранится в `localStorage["budget.cid"]`, в файлах его нет. Вводится заново на вкладке «Итоги» — возьмите из раздела «Координаты проекта» выше или из Google Cloud Console.

**Настройки Google Cloud.** Сам проект, включённый Drive API, список тестовых пользователей и разрешённые origins остаются в консоли и никуда не деваются. Трогать их нужно, только если поменяется адрес сайта: тогда новый origin надо дописать, иначе вход перестанет работать.

Установленная на телефоне PWA, кэш service worker и метка последней синхронизации восстанавливаются сами.
